# 框架无关的实现与验证规范

## 代码库发现

1. 读取仓库根规则、局部规则和可用技能。
2. 确认技术栈、构建工具、组件发现方式、路由方式、状态管理、样式方案和测试命令。
3. 搜索设计中所需能力的现有实现：图片、弹框、轮播、展开收起、图标、音视频、安全区和埋点。
4. 沿用相邻代码的命名、文件组织、数据流和样式习惯；不要从 Skill 中硬编码目录或框架结构。

## 组件与数据流

- 按职责拆分页面编排、媒体展示、信息摘要、列表和列表项等模块，禁止把全部代码集中在一个文件中；同时避免为了抽象而抽象。
- 优先使用属性向下、事件向上的清晰数据流；只在确实需要双向契约时使用双向绑定。
- 重复项使用稳定 key；派生索引、当前状态和显示列表使用计算逻辑。
- 复用公共组件的公开参数、插槽和暴露方法；需要增强公共组件时，添加默认不影响旧调用方的可选能力。
- 业务数据结构必须来自用户、设计或现有代码，不伪造接口字段和状态。

## 样式策略

- 遵循仓库已有样式体系，不强行引入另一套 CSS 方案。
- 不要使用带有默认样式的 HTML 标签承载视觉；涉及字体、间距、边框、背景等表现必须显式声明，或改用项目组件与样式类。
- 高复用布局使用项目惯用类或组件；一次性渐变、复杂背景和容易发生类名冲突的样式可放在行内或局部样式中。
- 动态业务内容使用正常文档流；固定尺寸只用于设计明确的控件和媒体框。
- 长文本必须明确换行、截断和溢出策略；容器需要设置正确的最小宽度和 box-sizing。
- 局部兼容样式必须说明目标平台和原因，避免扩大到全局。

## 资源与安全

- 使用仓库已有图片组件和资源加载方式；按任务要求决定远程资源、本地资源或占位符。
- 清理临时图片、下载文件、对象 URL、调试日志和 Demo 专用数据。
- 不在代码、Skill、示例、日志或回答中保存 MasterGo Token、Cookie、授权头或其他凭据。
- 不覆盖用户已有改动，不执行破坏性版本控制操作，除非用户明确要求。

## 验证

- 运行仓库规定的类型检查、静态检查、单元测试、构建或预览；优先修复 error 级别问题。
- 对修改范围运行针对性检查，避免为了通过检查而格式化或重构无关文件。
- 检查差异中的空白错误、编码、换行、临时文件、未使用资源和凭据残留。
- 在可用时进行浏览器或真实设备验证，覆盖：
  - 首次加载与重新打开。
  - 短文本、长文本、空内容和缺图。
  - 当前项重复点击、边界切换和快速连续操作。
  - 展开/收起、滚动、粘性元素和弹框关闭。
  - 移动端安全区、1px 边框、回弹和字体对齐。
- 无法运行某项验证时，说明具体原因、已完成的替代检查和剩余风险。
